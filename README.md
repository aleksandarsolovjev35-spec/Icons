# slice_icons.py — нарезка иконок из листов

Инструмент для листов вида «сетка плиток с тонкой светлой обводкой на чёрном фоне»
(здесь — `RPG Loot Icons 01/Part 1.jpg`, `Part 2.jpg`, 1800×1013, 10×5 плиток ~152 px).
Он сам находит рамки, режет каждую плитку **по внутренней грани обводки** (не по
внешней и не «на глаз»), чистит кант и поднимает до 256 px.

```
pip install pillow numpy opencv-python-headless

python3 slice_icons.py "RPG Loot Icons 01" -o out --debug
```

Пример вывода (100 иконок за ~30 с на двух листах):

```
out/
  RPG Loot Icons 01 Part 1/
    01_01.png 01_02.png ...      # PNG + JPG + WebP (см. --formats)
    manifest.json                # геометрия и QC по каждой плитке
    contact_sheet.png            # контактный лист для быстрой проверки глазами
    _debug/overlay.png           # найденные рамки и резы поверх листа
    _debug/edge_zoom.png         # 4 угла реза у 8 самых подозрительных плиток, ×5
  RPG Loot Icons 01 Part 2/...
```

(если на входе один файл, а не папка, всё пишется прямо в `-o`; `_debug/edge_zoom.png`
сортируется по «подозрительности»: сначала low_confidence и слабое покрытие линии,
красным показана линия фактического реза, квадратик угла = 56 px исходника.)

Имена файлов — `РЯДОК_СТОЛБЕЦ.png` (1-базные), в `manifest.json` у каждой плитки:

| поле | что это |
|---|---|
| `crop` / `crop_wh` | реальный рез `[x0, y0, x1, y1]` (x1/y1 exclusive) и его размер |
| `frame` | outer-бокс рамки (внешние грани штриха) — для контроля |
| `edge_outer`, `edge_t`, `edge_resp`, `cover` | по сторонам: позиция внешней грани, измеренная толщина штриха, отклик, покрытие линии |
| `why` | **почему сторона взята как взята**: `weak`, `relaxed`, `past-band`, `no-dark-outside`, `bright-outside`, `stroke-cap` |
| `low_confidence` | `true`, если хоть одна сторона помечена или плитка достроена решёткой |
| `rim_residue_px`, `rim_fix_px` | доля канта с остатком обводки / что подменил rim-fix |
| `art_left_on_frame_px`, `art_touches_edge` | арт остался за кадром (плохо) / арт упёрся в край (норма) |

Верхний уровень манифеста: `grid_rows/cols`, `tile`, `stroke_px` и `stroke_px_by_side`,
`line_level`/`gutter_level` (авто-калибровка листа), `residue_max`, `art_left_on_frame_max`,
`notes` (что вообще решил алгоритм: какие кандидатов сетки набирались, каким получилось окно,
сработал ли второй проход рёбер).

## Как это работает (кратко; полностью — в docstring модуля)

1. **Линейный детектор рамок.** Обводка = тонкая (1-4 px) светлая линия, снаружи почти
   чёрная. Отклик асимметричный: `g[y,x] − max(g[y−2..y−4, x])` и т. д. по 4 сторонам,
   сглаживание вдоль линии, поэтому рваный край арта отбрасывается, рамка остаётся.
2. **Полосы сетки** набираются из нескольких источников (линии, «решётка» с пропусками,
   полосы содержимого) и **светсясь по числу геометрических нарушений**, а не по силе
   отклика — иначе яркий край арта перетягивает сетку на себя.
3. **Каждое ребро каждой плитки уточняется локально**, в два прохода: второй добавляет
   prior типового размера плитки, потому что на листах с тонким каналом рамка соседа
   бывает ближе к границе полосы, чем своя.
4. **Внутренняя грань** = якорь + длина непрерывного «как линия» пробега (яркость в
   коридоре вокруг уровня линии листа + почти бесцветность). Раздутый артом пробег
   урезается по типовому размеру плитки (`why: stroke-cap`). Режем по внутренней грани,
   `--inset 0` по умолчанию.
5. **Чистка и апскейл** пресетом `--pipeline quality`: denoise(3) в исходнике → Lanczos →
   denoise(6) → unsharp 0.6 с порогом по локальной контрастности → denoise(3).
   Пиксель-арт требует `--pipeline pixel` (никакого сглаживания до ресайза, иначе
   исчезают 1-2px детали).

## Главные флаги

| флаг | зачем |
|---|---|
| `--size` | целевой размер, по умолчанию 256 |
| `--inset` | запас внутрь от грани (0 = строго по грани); 1 — страховка на грязный канал |
| `--grid 5x10` | **аварийный** режим: принудительная равномерная сетка, если обводку не найти |
| `--line-thresh` | порог отклика обводки (0 = авто по шуму листа); нужен на тёмных/тусклых листах |
| `--pipeline` | `quality` (дефолт) \| `fast` \| `soft` \| `pixel` \| `raw` |
| `--formats` | что писать, по умолчанию `png`; `png,jpg,webp` — рядом конверты |
| `--fit` | `stretch` (дефолт) \| `square` \| `pad` — как из почти-квадрата 150×151 делать 256×256 |
| `--matte` | чёрный фон плитки → альфа (PNG RGBA) |
| `--debug` | `_debug/overlay.png` + `_debug/edge_zoom.png` |
| `--dry-run` | только геометрия и QC, без записи иконок |
| `--no-complete` | не достраивать пропущенные полосы решёткой |

## Как проверять результат

1. `contact_sheet.png` — сразу видно срезанный/уехавший арт.
2. В манифесте — `low_confidence` и непустой `why`: такие плитки открываются в
   `_debug/overlay.png` (оранжевый = найденная рамка, голубой = фактический рез) и в
   `_debug/edge_zoom.png` (углы реза, ×5).
3. `art_left_on_frame_max` > 0.5 — где-то арт остался за кадром (рез слишком узкий);
   `residue_max` > 0.05 — где-то в кадре осталась серая строка обводки.

## Тесты

```
python3 selftest_slice_icons.py        # ~70 с
```

Генерирует синтетические листы с известной истиной (разные плитки, толщины обводки
1/2/4 px, канал, джиттер ±3 px, JPEG q78, тусклые рамки, пиксель-арт, `--grid`) и
сверяет **рез с истиной по пикселям**, отсутствие остатков рамки в кадре, несрезанность
арта у грани и RMSE с эталонным кадром. Текущий прогон: все кейсы точны до 0-1 px;
два заведомо патологических листа (`gutter 3 px` + арт впритык и `--grid` по шумному
фону) проверяются по медиане расхождения — их допуски и причины описаны прямо в тесте.

## Известные пределы точности

* Рука написанная рамка на реальных листах местами 1 px, местами 2 px, местами «съедена»
  артём впритык: из-за этого размер плиток на `RPG Loot Icons 01` — 150×150 у 40/42 из
  50 плиток, остальное ±1 px, и это совпадает с ручной разметкой источника.
* `--grid` не знает про рамки: граница равномерной полосы может стоять посередине
  канала, тогда край плитки съезжает до половины канала. После `--grid` обязателен
  визуальный контроль.
* `--engine` — это только ядро ресемплинга; реальную разницу даёт `--pipeline`.
