# Поиск серо-белых рамок на листах иконок

## Быстрый старт (одна кнопка)

См. `README_START.md` в корне. Коротко: двойной клик по `run_all.bat`
(Windows) или `./run_all.sh` — скрипт ставит зависимости, качает модель,
прогоняет все листы и складывает результат в `icons_256/`.

## Что делает

На каждом листе (1800×1013, тёмный фон) находит тонкие серо-белые рамки слотов
и обводит их **красным** прямо поверх листа. Координаты всех рамок пишутся в
CSV/JSON.

Требования: `python3 -m pip install opencv-python-headless numpy`

## Запуск

```bash
python3 tools/detect_frames.py             # разметить все листы (annotated/preview/)
python3 tools/detect_frames.py --scale 1  # то же в полном разрешении (annotated/full/)
python3 tools/make_report.py               # галерея annotated/index.html + контактные листы
```

Один лист:

```bash
python3 tools/detect_frames.py "RPG Loot Icons 01/RPG Loot Icons 01 Part 1.jpg"
```

## Алгоритм (коротко)

1. **Жёлоба.** Фон листов чёрный, поэтому межслотовые полосы ищутся как
   столбцы/строки, у которых 99-й процентиль яркости остаётся почти чёрным по
   всей длине (это отсекает тёмные места *внутри* иконок).
2. **Сетка.** Середины жёлобов = номинальные границы слотов; количество строк и
   столбцов получается само (8×5, 10×5, 11×6 — любой вариант).
3. **Уточнение.** В каждом жёлобе ищутся **две** линии — правая грань левого
   слота и левая грань правого (жёлоб делится пополам: слева берём ближайшую к
   середине линию, справа — ближайшую к середине). Кандидат — «плато» тонкой
   линии: ярче соседей на 2 px, яркость 30…225, почти постоянная вдоль всей
   стороны. Это важно: если искать по одной линии на границу, вторая грань
   теряется, и рамка получается уже настоящей (подхватывался контур иконки).
4. **Контроль.** Ширина и высота всех слотов листа приводятся к медиане листа
   (сетка регулярная, проверено: попадание в линию от этого только улучшается),
   пересечения раздвигаются; если линии не подтвердились (confidence < 0.15) —
   лист помечается `no_frames`, рамки не рисуются.

Геометрия на этой коллекции: рамка слота = линия в линию, 152–155 px
(внутри 180 px ячейки сетки), т.е. ровно то, что «физически не может быть
больше 160 px».

Цвета разметки: **красный** — уверенная рамка, **оранжевый** — линия не
подтвердилась (бокс взят по сетке), **серый + `NO FRAMES`** — рамок на листе нет.

## Результат на этой коллекции (234 листа)

- рамок найдено — **11 300**;
- листов с уверенной разметкой — **226**, все слоты 10×5, pitch ≈ 180 px;
- листов без рамок — **8** (`RPG Loot Icons 39/40`, `RPG Weapon Icons 09`,
  `RPG Weapon and Armor 15`) — на них сетка слотов показана серым;
- **ни одной рамки больше 160 px**: размеры 135…155 px, медиана 153;
- контроль попадания в линию по всем 45 200 сторонам: средний контраст 52.5,
  не подтвердилось 5.6 % сторон (линия перекрыта артом — там размер выровнен
  по сетке листа).

## Объёмная рамка-бортик (без красной линии)

```bash
python3 tools/style_frame.py                       # все листы -> styled/ (0.45x)
python3 tools/style_frame.py --limit 3 --scale 1   # полное разрешение
python3 tools/style_frame.py --variant soft|deep|inset
python3 tools/style_frame.py --radius 0                          # прямые углы, без скругления
python3 tools/cut_icons.py --style sharp --radius 0 --n 1 --out cutouts_styled
```

Как устроен бортик (`style_box`): считаем signed distance до скруглённого
прямоугольника слота и по нему рисуем

1. тело борта — почти чёрное, с градиентом поперёк (светлее к внешней кромке);
2. тонкую световую линию по внешней кромке на светлой стороне (верх-лево);
3. внутреннюю тень: мягкая, глубокая, сильнее сверху-слева;
4. внешнюю падающую тень под бортом (снизу-справа);
5. слабый блик по нижней-правой внутренней кромке.

Всё через сглаженные маски → антиалиасинг на любом масштабе, и рамка
масштабируется без потери качества. Варианты: `soft` (тонкий), `deep`
(выраженный выступ, по умолчанию), `inset` (утопленный слот), `sharp`
(без скругления). Радиус скругления можно задать вручную: `--radius 0` —
прямые углы.

`sharp` — это `deep` (свет сверху-слева) с прямыми углами; `sharp_bottom` —
то же, но свет снизу (`light="bottom"`: верхняя кромка тёмная, глубина
читается снизу). Источник света можно задать и вручную: `--light bottom`.
Внешняя часть при `radius = 0` считается по L∞-метрике (`sharp_outside`),
поэтому прямые углы сохраняются и у внешней кромки борта.

## Чистка иконок от JPEG-шума

```bash
python3 tools/analyze_noise.py samples/icon_sharp_bezel.png    # разбор шума
python3 tools/clean_icon.py samples/icon_sharp_bezel.png -o samples/icon_clean.png
python3 tools/clean_icon.py in.png -o out.png --chroma 1.0 --luma 0.8
```

Что за шум (замерено на листах): **«сыпь» на заливках** — там, где по рисунку
ровный цвет, гуляет мелкая структура ±3..10 ед. яркости плюс блочность 8×8
(грубое квантование JPEG); **цветной шум по хроме** (4:2:0); **звон у светлых
контуров**.

Как чистится (`clean_fill`) — **NLM + возврат деталей**:

1. Каналы LAB чистятся `cv2.fastNlMeansDenoising`: каждый пиксель заменяется
   средним по похожим на его окружение фрагментам кадра. Заливка усредняется,
   кромки и скругления не «платофицируются» — нет ступенек и надрезов.
2. `restore_detail()` возвращает исходную фактуру, раздельно по масштабам.
   Картинка раскладывается на две полосы:
   * **средняя** (`med`) — то, что переживает медиану 3×3: пятна, мраморность,
     мягкая штриховка. Это и есть «узор», который смывает NLM, — её возвращаем
     почти всегда (в ровной заливке `med` и так совпадает с чисткой, поэтому шум
     оттуда не лезет);
   * **тонкая** (`src - med`) — однопиксельная крупа и кромки. Её возвращаем
     только там, где есть средняя структура: на одиночной крапинке в пустой
     заливке вес нулевой (крупа остаётся вычищенной), а тонкая линия, ободок или
     контур возвращаются целиком.
   Цвет возвращается слабее яркости — цветной шум заметнее всего.
   Сила — `--detail 0..1`.
3. `clean_flats()` — добивает остаточный шум **только там, где нет узора**.
   Локальный разброс яркости (std в окне 9×9) отличает мраморность, штриховку и
   блики от ровной заливки, фона и мягкой тени. Где разброс ниже `--flat-T`,
   дополнительно идёт медиана: она снимает остаточную крупу и блочность 8×8, но
   не трогает низкие частоты — сам градиент тени остаётся на месте. Маска мягкая,
   стыка между зонами не видно. Порог — `--flat-T 0..40` (0 — выключить).
4. `soften_edges()` — при желании смягчает полосу кромок (`--soft-edges 0..1`).

Режимы:

| режим | hL | detail | flat_T | сохранность узора (corr) |
|---|---|---|---|---|
| `soft` | 8 | 0.95 | 10 | 0.995 |
| **`normal`** (по умолчанию) | 14 | 0.90 | 12 | **0.994** |
| `strong` | 20 | 0.75 | 14 | 0.990 |
| `max` | 28 | 0.55 | 16 | 0.971 |

Движки-альтернативы: `--preset freq` (частотный), `--protect/--iters` (mean shift).

Замеры `normal` (узор — корреляция среднего слоя с исходником, 1.0 = не тронут):

| метрика | череп: до → после | зелье: до → после |
|---|---|---|
| сохранность узора | — → **0.994** | — → **0.990** |
| шум на заливках | 1.29 → **0.92** | 0.73 → **0.56** |
| шум яркости | 0.29 → **0.16** | 0.09 → **0.05** |
| цветной шум a/b | 0.31 → **0.20** | 0.13 → **0.07** |
| резкость контуров | 61.2 → 63.8 | 53.2 → 55.2 |

Подбор баланса «чистота / узор»:

```bash
python3 tools/clean_icon.py in.png -o out.png                 # normal
python3 tools/clean_icon.py in.png -o out.png --flat-T 20     # чистить шире (сильнее)
python3 tools/clean_icon.py in.png -o out.png --flat-T 0      # не трогать заливки отдельно
python3 tools/clean_icon.py in.png -o out.png --detail 1.0    # фактура как есть
```

Сравнения: `samples/two_icons_clean.jpg` (череп и зелье, ×3),
`samples/skull_pattern_zoom.jpg` (низ черепа, узор, ×6),
`samples/skull_fill_zoom.jpg` (заливка между глазами, ×10),
`samples/icon2_zoom.jpg` (зелье, стекло, ×8).

## Апскейл иконки до 256×256

```bash
python3 tools/upscale_icon.py in.png -o out.png            # 256×256, EDSR
python3 tools/upscale_icon.py in.png -o out.png --sharp 0  # без доводки
python3 tools/upscale_icon.py in.png -o out.png --size 512 # другой размер
```

Что делает:

1. **EDSR ×4** (OpenCV `dnn_superres`) — нейросеть достраивает кромки и мелкую
   фактуру вместо размытия, как при билинейке/ланцоше. Модель ~38 МБ качается
   один раз в `tools/models/` (в git не кладём, см. `.gitignore`).
   Нужен `opencv-contrib-python-headless`.
2. **INTER_AREA до 256×256** — точная выборка без повторного звона.
3. **Лёгкий unsharp по L** (0.4, σ0.8) — возвращает микроконтраст, который
   съедает ресемплинг. Сильнее не надо: у контуров появляется гало (`--sharp`).

Сеть гоняется **только по каналу яркости**, цвет (a/b) поднимается Lanczos.
Через BGR сеть подтягивает насыщенность (у зелья S +3) и оттенок уезжает;
через L цвет остаётся ровно тем же (mean и std a/b совпадают), резкость та же —
рисунок и так держится на яркости.

Замеры на наших иконках (166×167 и 160×160 → 256×256):

| | череп | зелье |
|---|---|---|
| резкость (HF) lanczos → EDSR | 3.27 → **3.49** | 2.32 → **2.51** |
| гало у контуров | 15.0 → **14.4** | — |
| оттенок a/b | 127.3/133.8 → 127.3/133.9 | 143.9/116.9 → 143.8/117.0 |
| время на иконку | ~11 c | ~9 c |

Сравнения: `samples/upscale_compare.jpg` (nearest / lanczos / EDSR, 256),
`samples/upscale_zoom.jpg` (фрагмент ×5), `samples/upscale_potion.jpg`.

Пример на оружии (булава, `RPG Weapon Icons 05/file (84).jpg`, слот 1):
`samples/weapon_compare.jpg` — ДО / чистка+nearest / чистка+lanczos /
чистка+EDSR; `samples/weapon_zoom.jpg` — та же головка булавы крупно.
Результаты: `samples/weapon/mace_raw.png` (167×167),
`mace_clean.png`, `mace_256.png`. Чистка `normal`: шум на заливках 0.83 → 0.61,
шум яркости 0.10 → 0.04, резкость 53.8 → 55.6; апскейл: резкость 2.16 → 2.34,
цвет (a/b на насыщенных пикселях) 132.5/134.9 → 132.4/134.4.

## Улучшение одной иконки: из 56×56 в 512×512

`enhance_icon.py` — довести одиночную маленькую иконку (шум, JPEG, обрезанная
рамка слота по углам) до состояния «не стыдно в магазин». Это не то же самое,
что пакетный прогон: там задача — аккуратно нарезать и слегка почистить
1130 иконок, здесь — выжать всё из одной.

```bash
python3 tools/enhance_icon.py icon.jpg                      # 256 / 512 / 1024
python3 tools/enhance_icon.py icon.jpg --variant rich        # смелее по цвету и свету
python3 tools/enhance_icon.py icon.jpg --variant faithful    # ближе к исходнику
python3 tools/enhance_icon.py icon.jpg --sizes 128 512       # только нужные размеры
python3 tools/enhance_icon.py icon.jpg --passes 1            # без второго прохода сети
python3 tools/enhance_icon.py icon.jpg --no-sr               # без сети, только чистка
```

Результат — `enhanced/<имя>_<размер>.png` и `enhanced/<имя>_sravnenie.png`
(«как было / как стало»).

Почему это четыре шага, а не один `resize`:

1. **Ремонт кромки.** У вырезанной иконки по периметру остаются пиксели рамки
   листа — светло-серые (S < 60) и яркие (V > 90). Апскейл раздувает их в
   яркую кайму по краю кадра. Такие пиксели ищутся только в полосе 3 px у
   края и заливаются медианой соседнего фона; углы 4×4 чистятся всегда.
2. **Апскейл Real-ESRGAN ×4** (`sr_ncnn`). Маленькая иконка 56 px идёт
   двумя проходами (56 → 224 → 896): один проход держит форму, но оставляет
   ступеньки на скруглениях, второй уточняет градиенты, блики и кромку
   самоцвета. Второй проход включается только если после первого кадр меньше
   половины нужного размера — готовый вырез 150 px уже на первом проходе даёт
   600, и гонять его ещё раз бессмысленно. Всё, что больше 256 px по стороне,
   режется на куски 96 px с полями 16 px (`sr_tiled`): ncnn держит блобы
   пропорционально площади входа, и на кадре 208×208 модель съедает ~2.7 ГБ —
   машину с 4 ГБ просто убивает OOM. Шов между кусками гасят плавные веса.
3. **Чистка фона.** Сеть поднимает старую JPEG-крупу в тёмных участках, и
   после усиления контраста фон идёт полосами. NLM по яркости включается
   только там, где «темно и гладко» (V < 70, амплитуда мелкой структуры < 6),
   поэтому тень и свечение вокруг иконки остаются, а крупа уходит.
4. **Полировка.** Локальный контраст в средних тонах (в тенях вес 0), два
   unsharp (σ ≈ size/420 и size/512), свечение по ярким пикселям (золото и
   самоцвет горят своим же цветом), вибранс, тепло и виньетка. Все радиусы
   заданы в долях размера, поэтому 256 и 1024 выглядят одинаково.

Насыщенность — именно вибранс, а не «умножить S на коэффициент»: умножение
вслепую выкручивает уже насыщенные места, и на соседней иконке (розовый
самоцвет в кольце) камень становится кислотно-красным, а бирюза неоновой.
Здесь прибавка полная на сером и падает до нуля там, где пиксель уже
насыщен (`saturate(k, protect)`).

Сравнения лежат в `samples/enhanced/`:
`varianty_original_faithful_balanced_rich.png` — исходник и три пресета
полировки подряд, `inv_earthenring_sravnenie.png` — «как было / как стало».
