# Как получить все иконки 256×256

## Windows — двойной клик

Нажми **`run_all.bat`**. Скрипт сам:

1. найдёт Python (нужен 3.10+; при установке отметь «Add Python to PATH»);
2. создаст окружение `.venv` и поставит `numpy` + `opencv-contrib-python-headless`;
3. возьмёт модель апскейла (FSRCNN уже лежит в репозитории — интернет нужен только
   для установки пакетов);
4. нарежет **все** листы и почистит каждую иконку от JPEG-шума;
5. соберёт превью в `samples/` и откроет папку с результатом.

Результат: **`icons_cut/<папка>/<лист>__slotNN.png`** — 11 300 файлов, ~4 минуты.
Размер — **родной, максимальный**: 146–155 px. **Без апскейла и без рамки**,
пиксель в пиксель, поэтому ничего не размывается.

Режем по **внутренней стороне белой рамки**, сканируя **каждую строку и столбец**:
идём от края слота внутрь, пока пиксель серый/белый (это линия), и
останавливаемся на первом реально чёрном пикселе фона (яркость ≤ 30, без
цвета). Пиксель цветной — значит рисунок, дальше не идём, картинку не режем.

Смещения собираются по всем строкам, берётся 85-й процентиль: медиана не даёт
паре «дырок» исправить результат, а рисунок у края не растягивает вырез.

Замер по 1130 иконкам: пикселей серо-белой линии на кромке **медиана 0.17%**
(было 12.8% при замере по одной центральной линии), полностью чистых иконок
**82.8%**, размер 133–154, медиана 150.

## macOS / Linux

```bash
chmod +x run_all.sh
./run_all.sh
```

## Полезные варианты

```bat
run_all.bat --limit 5          :: только первые 5 листов (проверка)
run_all.bat --slots 3          :: по 3 иконки с листа
run_all.bat --smooth           :: EDSR вместо FSRCNN (медленнее, чуть мягче)
run_all.bat --out my_folder    :: сложить результат в другую папку
run_all.bat --up 256           :: апскейл до 256 (мягче оригинал, но крупнее)
run_all.bat --frame sharp --up 256  :: то же + чёрная рамка 10 px
run_all.bat --cut line         :: границы по внешнему краю белой линии
run_all.bat --cut corner       :: границы по однотонным чёрным углам слота
```

Напрямую, без батника:

```bash
python3 tools/run_all.py
```

## Что происходит внутри

| шаг | инструмент |
|---|---|
| поиск слотов на листе | `tools/detect_frames.py` |
| **рез по внутренней стороне рамки** | `batch_all.py` -> `crop_by_inner_edge()` |
| чистка от JPEG-шума | `tools/clean_icon.py` (`--preset normal`) |
| пакетный прогон | `tools/batch_all.py` |
| превью и отчёт | `tools/make_batch_previews.py` |

## Алгоритм нарезки (актуальный)

По умолчанию иконка отдаётся в **родном размере, без апскейла**, и режется
**по внутренней стороне белой рамки**:

```
1. detect_frames  -> bbox слота (проходит по центру белой линии)
2. для КАЖДОЙ стороны слота смотрим 4 px внутрь и 2 px наружу:
     линия рамки - САМАЯ ЯРКАЯ нейтральная полоса у края
     (она идёт по всей стороне, поэтому ярче и ровнее рисунка)
     если рисунок перекрывает линию (например, лист касается края),
     берём её по серым пикселям: их может быть всего 25%, но они
     яркие и очень ровные вдоль стороны (разброс <= 12)
     режем на 1 px глубже неё - по её внутренней кромке
3. вырез 1:1 -> clean_fill -> PNG
4. кадр добивается до 151x151 РОДНЫМ тёмным фоном листа (без масштабирования)
```

Почему «самая яркая полоса», а не скан «иди внутрь, пока не станет чёрным»:
под линией часто идёт светлый рисунок — серебро, мех, светлое дерево. Цвет
у него такой же нейтральный, как у линии, поэтому скан принимал рисунок за
продолжение линии и уходил на 10–11 px, срезая саму иконку. Линия при этом
ровная вдоль всей стороны, а рисунок — нет, и по краю он всегда темнее.

Четвёртый шаг важен: слоты на разных листах разного размера (133–154 px), поэтому
мелкие иконки не растягиваются до общего размера, а встают в кадр 151x151,
и им по сторонам дорисовывается тёмный фон — цвет берётся из настоящего фона
листа рядом со слотом. Иконка остаётся пиксель в пиксель, резкость не падает.

Почему по полосе, а не по одному пикселю: яркость считается по всей стороне
слота сразу (медиана вдоль строки или столбца), поэтому одиночный блик или
тень рисунка не сдвигают границу. Раньше граница искалась сканом по каждому
пикселю от края — и на светлом рисунке скан проскакивал линию.

Результат замера по 1130 иконкам (234 листа × 5 слотов):

| метрика | значение |
|---|---|
| остаток линии на кромке | **0%** сторон (проверка тем же критерием, что у детектора) |
| самая светлая полоса по краю (рисунок) | 0.42% сторон |
| размер кадра | **ровно 151×151 у всех** |

Ключи: `--cut inner` (по умолчанию), `--cut line` (по внешнему краю линии,
линия остаётся как рамка), `--cut corner` (по однотонным чёрным углам).
Апскейл (`--up 256`) и чёрный бортик (`--frame sharp`) — только явно, и
рамка в этом случае рисуется **последней**, по готовому кадру.

Превью после прогона: `samples/batch_contact_sheet.jpg`,
`samples/batch_montage.jpg`, отчёт — `samples/batch_summary.csv`.
Примеры одиночных иконок — `samples/examples/`.

## Апскейл до 256 (Real-ESRGAN)

`--up 256` поднимает вырез до 256×256 **с достройкой деталей**: сеть не
интерполирует пиксели, а прорисовывает штрихи, чешуйки, нити ткани и мелкие
надписи. Движок — Real-ESRGAN (`realesrgan-x4plus-anime`, ×4) на CPU через
`ncnn`, без torch и без Vulkan; ~3 с на иконку.

```
python3 tools/run_all.py --up 256          # весь прогон
python3 tools/upscale_icon.py in.png       # одна иконка
python3 tools/sr_ncnn.py in.png -o out.png --model realesrgan-x4plus-anime
```

Ставится один раз: `pip install ncnn realesrgan-ncnn-py` — веса лежат внутри
пакета. Если их нет, прогон сам переключится на EDSR и предупредит.

**Видеокарта.** Сеть умеет считать через Vulkan (`--device gpu`), это в
10–30 раз быстрее CPU. По умолчанию `--device auto`: если Vulkan видит
видеокарту — берётся она, иначе CPU. На GPU прогон сам ставит `--jobs 1`,
чтобы несколько процессов не делили видеопамять. Если вместо GPU написано
«GPU не найден» — на Windows нужен свежий драйвер (Vulkan идёт в комплекте
с драйвером NVIDIA/AMD/Intel), на Linux — `libvulkan1` и ICD драйвера.

```
python3 tools/run_all.py --up 256 --device gpu    # явно на видеокарте
python3 tools/run_all.py --up 256 --device cpu    # явно на процессоре
```

Почему не `cv2.dnn_superres` (EDSR/FSRCNN): они обучены на фотографиях и на
иконках размазывают заливки — резкость по лапласиану падала с 920 до 125 при
149→256. У Real-ESRGAN после апскейла она 700–3500, то есть детальность
остаётся на уровне оригинала. Сравнение — `samples/upscale_preview/`, там же
рядом лежат варианты `__lanczos` для наглядности.

Порядок обработки: вырез (без добивки фоном) → сеть ×4 → `INTER_AREA` до 256
→ сглаживание ровных зон → лёгкий unsharp по яркости.

Ключи: `--sr anime` (по умолчанию при `--size`), `--sr edsr` — старый путь.

## Окно и прогресс

Батник печатает весь прогресс (шаги 1/5…5/5, по строке на каждый лист) и в
конце **сам делает паузу** — «Press any key to close this window». Окно можно
свернуть, работа продолжится.

Весь вывод параллельно пишется в **`run_log.txt`** в корне: если окно всё же
закрылось, открой этот файл — там будет видно, на каком шаге остановилось.

## Если что-то пошло не так

- **«Python не найден»** — поставь Python 3.10+ и включи «Add Python to PATH».
- **Ошибка `dnn_superres`** — батник сам переустановит contrib-сборку opencv;
  вручную: `pip install --force-reinstall opencv-contrib-python-headless`.
- **Окно открылось и сразу закрылось** — раньше так и было: файл лежал в
  репозитории с Unix-переводами строк, а `cmd.exe` такой батник не дочитывает.
  Исправлено: `run_all.bat` хранится с CRLF, за это отвечает `.gitattributes`.
  Если у тебя старая копия — обнови репозиторий (`git pull`), либо почини файл
  в PowerShell:
  ```
  $p="$PWD\run_all.bat"; $c=Get-Content $p -Raw; [IO.File]::WriteAllText($p, ($c -replace "`r?`n","`r`n"))
  ```
- **В консоли «кракозябры» или падение `UnicodeEncodeError`** — было из-за
  рассинхрона кодировок. Вывод Python-скрипта идёт либо в консоль (cmd.exe,
  cp866), либо в **пайп** — когда `tools/run_all.py` запускает
  `tools/batch_all.py` и читает его вывод; для пайпа Python берёт cp1251, а
  символа `->` (U+2192) в cp1251 нет — отсюда `UnicodeEncodeError` на шаге 3/5.
  Исправлено: `tools/_console.py` в настоящей консоли переключает её на UTF-8
  (`SetConsoleOutputCP(65001)`) и выводит utf-8; в пайпе кодировку не трогает
  (дочерние процессы пишут utf-8 через `child_env()`), но включает
  `errors="replace"` — уронить прогон не может никакой символ.

  **Важно:** если ошибка всё ещё видна — значит, у тебя старая копия файлов.
  Проверь, что `tools/_console.py` существует, а в `tools/batch_all.py` есть
  строка `setup()` в начале `main()`. Обнови репозиторий (`git pull`), либо
  скачай ZIP заново.
- **`--smooth` не качает EDSR** — скачай `EDSR_x4.pb`
  (<https://github.com/Saafke/EDSR_Tensorflow/tree/master/models>)
  и положи в `tools/models/`.
